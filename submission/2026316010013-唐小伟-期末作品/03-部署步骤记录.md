## 2. SSH 登录服务器

本地生成专用部署密钥（不把密码写进脚本）：

```bash
ssh-keygen -t ed25519 -C "dsh-deploy-sooyaaa" -f _scratch/deploy_key -N ""
cat _scratch/deploy_key.pub
```

在腾讯云控制台的实例「密钥」或 `~/.ssh/authorized_keys` 中加入公钥后，本地登录：

```bash
ssh -i _scratch/deploy_key ubuntu@43.136.175.239
```

登录成功后可确认身份与 sudo 权限：

```bash
whoami        # ubuntu
sudo -n true && echo "sudo ok"
```

![SSH 登录服务器](images/deploy-02.png)

> 排错记录：最初把公钥加到了 `root` 用户，导致 `root@43.136.175.239` 一直 `Permission denied (publickey,password)`；查看 `ssh -v` 输出发现密钥已被服务器「拒绝」，改用 `ubuntu` 用户登录成功。云厂商默认禁止 root 直接登录，使用默认用户 + sudo 是正确做法。

## 4. Nginx 配置（root 路径等）与语法检查（nginx -t）

创建站点配置 `/etc/nginx/sites-available/mysite`（完整内容见仓库 `deploy/nginx.conf`）：

```nginx
server {
    listen 80;
    listen [::]:80;
    server_name _;

    root /var/www/mysite;
    index index.html;

    charset utf-8;

    access_log /var/log/nginx/mysite.access.log;
    error_log  /var/log/nginx/mysite.error.log warn;

    add_header X-Content-Type-Options nosniff always;
    add_header X-Frame-Options SAMEORIGIN always;
    add_header Referrer-Policy strict-origin-when-cross-origin always;

    gzip on;
    gzip_comp_level 5;
    gzip_min_length 512;
    gzip_types text/plain text/css application/javascript application/json image/svg+xml;

    location ~* \.(?:css|js|svg|jpg|jpeg|png|webp|gif|ico|woff2?)$ {
        expires 7d;
        add_header Cache-Control "public";
        try_files $uri =404;
    }

    error_page 404 /404.html;

    location / {
        try_files $uri $uri/ =404;
    }

    location ~ /\.(?!well-known) {
        deny all;
    }
}
```

启用站点并检查语法：

```bash
sudo ln -sf /etc/nginx/sites-available/mysite /etc/nginx/sites-enabled/mysite
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t
# nginx: configuration file /etc/nginx/nginx.conf test is successful

sudo systemctl reload nginx
```

## 5. 网站文件传输到服务器

方式一（推荐）：使用仓库中的一键脚本，本地打包 → scp 上传 → 远端解压 → 重载：

```bash
SSH_KEY=_scratch/deploy_key ./scripts/deploy.sh ubuntu@43.136.175.239
```

脚本实际执行的关键命令：

```bash
tar -czf mysite-<时间戳>.tar.gz index.html 404.html style.css main.js favicon.svg resume.pdf
scp -i _scratch/deploy_key mysite-<时间戳>.tar.gz ubuntu@43.136.175.239:/tmp/
ssh -i _scratch/deploy_key ubuntu@43.136.175.239 "
  sudo mkdir -p /var/www/mysite
  sudo tar -xzf /tmp/mysite-<时间戳>.tar.gz -C /var/www/mysite
  sudo chown -R www-data:www-data /var/www/mysite
  sudo chmod -R 755 /var/www/mysite
  rm -f /tmp/mysite-<时间戳>.tar.gz
  sudo nginx -t && sudo systemctl reload nginx
"
```

方式二：手工 scp 上传：

```bash
scp -i _scratch/deploy_key index.html style.css main.js 404.html favicon.svg resume.pdf \
  ubuntu@43.136.175.239:/tmp/
ssh -i _scratch/deploy_key ubuntu@43.136.175.239
sudo cp /tmp/index.html /tmp/style.css /tmp/main.js /tmp/404.html /tmp/favicon.svg /tmp/resume.pdf /var/www/mysite/
sudo chown -R www-data:www-data /var/www/mysite
```

## 7. 一次完整的个人网站版本功能更新演示

以「修改页脚版权年份 + 新增一条技能标签」为例，完整走一遍「本地修改 → 提交推送 → 服务器更新 → 刷新验证」：

1）本地修改并预览：

```bash
# 修改 index.html（示例：页脚年份、技能标签）
python -m http.server 8080
# 浏览器打开 http://localhost:8080 确认改动正常
```

2）提交并推送到 GitHub：

```bash
git add index.html
git commit -m "content: 更新页脚年份与技能标签"
git push origin main
```

3）服务器更新（拉取或重新上传，二选一）：

```bash
# 方式 A：服务器直接拉取仓库（推荐，命令可追溯）
ssh -i _scratch/deploy_key ubuntu@43.136.175.239
sudo git -C /var/www/mysite pull   # 若站点目录为 git 仓库
sudo systemctl reload nginx

# 方式 B：本地重新执行部署脚本
SSH_KEY=_scratch/deploy_key ./scripts/deploy.sh ubuntu@43.136.175.239
```

4）刷新浏览器验证：`http://43.136.175.239/` 页面出现新内容，`git log` 中可看到本次提交。

## 附：常用运维命令

```bash
sudo systemctl restart nginx     # 重启
sudo systemctl reload nginx      # 平滑重载（改配置后）
sudo tail -f /var/log/nginx/error.log
sudo tail -f /var/log/nginx/mysite.access.log
```

回滚方式：`git checkout <上一个版本tag> -- index.html style.css main.js` 后重新部署；或 `git revert <提交>` 再推送部署。
