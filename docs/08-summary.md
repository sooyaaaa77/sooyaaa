## 1. 项目概述

### 1.1 目标

1. **课程交付**：按老师要求完成一个可公网访问的个人介绍网站，并留下完整的过程材料（需求、设计、计划、部署、测试、总结）。
2. **求职作品集**：能放进简历、在面试时打开给面试官看，内容以「我做过什么」为主。
3. **流程示范**：本项目的重点不是编码量，而是把「需求 → 设计 → 计划 → 开发 → 部署 → 测试 → 复盘」跑通一遍，学会用 Git 和文档管理自己的项目。

### 1.2 定位

- 纯静态站点：HTML + CSS + 原生 JavaScript，零构建、零第三方依赖、无外链字体与库，内容直接写在 `index.html`。
- 视觉为白底编辑风格（参考 pudding.cool）：白色主底、`#f7f7f7` 交替区块、粗体无衬线标题、等宽大写标签、彩色标签与黄色关键词高亮；同时保留黑底深色主题。
- 内容主线调整为 **UE5 × 传媒 / 虚拟制片 / 影像后期**，与 2026 届求职方向一致；不再是通用的「后端开发」模板。
- 单页结构 + 锚点导航，适合作品集这种「一屏讲清一个人」的场景。
- 两周（D1–D10）完成，范围可砍；**部署、文档、Git 记录不可砍**。

## 3. 关键决策与取舍

| 决策 | 理由 | 代价 |
|---|---|---|
| 纯静态，不用 Vue / Next | 单页展示型站点无数据源，零构建让部署与排错都简单；求职作品集更看重「能上线、能讲清」，框架收益低 | 无组件复用，重复区块靠复制；交互要手写原生 JS |
| 手写 Nginx，不用宝塔 / 一键包 | 老师硬性要求；能逐条解释配置含义，面试时也是加分项 | 命令行操作，出错排查慢，没有可视化面板 |
| 两周内不做域名与 HTTPS | 域名实名/备案周期不可控，证书续期又多一个变量；IP + HTTP 足以完成验收 | 浏览器显示「不安全」，链接不好看，不适合长期放在简历 |
| 用公网 IP 直接访问 | 零配置、零等待，能把时间留给内容与打磨 | IP 可能变化；无法使用域名相关的缓存/CDN 能力 |
| 内容先占位后替换 | 先把结构、样式、部署流程跑通，避免被文案卡住；TODO 注释标记位置 | 交付前必须替换，否则「示例」会被当成真实经历（DEF-01） |
| 单提交单回滚点 | 每次提交只做一件事，出问题能精确回退，也方便老师看到过程 | 提交次数多，需要自律保持粒度 |
| 白底编辑风格（v0.2） | 用户明确要求参考 pudding.cool；纸白底 + 彩色标签信息密度高，贴合作品集与传媒方向的气质 | 用色需要克制，否则像模板；深色主题要单独调一套颜色 |
| 移除自定义光标（v0.2） | 用户要求；系统默认光标更稳、对可访问性更友好，也少维护一个 JS 模块 | 少了一个装饰性记忆点，页面更「素」 |
| 内容转向 UE5 × 传媒（v0.2） | 求职方向明确，项目、技能、首屏文案自洽，面试时讲得通 | 原后端向文案与技能组整体返工，测试用例同步修改 |

### 4.3 遇到的问题与解决

| 问题 | 现象 | 处理方式 |
|---|---|---|
| AI 生成代码需要人工核对 | 结构与样式代码量大，容易出现重复选择器、未定义变量、语义不当 | 逐段阅读后再合入；`node --check` 与标签闭合检查兜底；不确定的写法删掉而不是留着 |
| 视觉方向调整（v0.2） | 原纸张米色 + 深色区块的风格与用户想要的「pudding 白底编辑风」不符 | 整体换色板与排版：白底、`#f7f7f7` 交替、等宽大写标签、彩色标签、黄色高亮；深色主题保留并单独调对比度 |
| 删除自定义光标（v0.2） | 实现分散在 HTML 结构、CSS 规则、JS 模块三处，容易删漏 | 三处同步删除后做全局搜索（`cursor-ring`、`data-cursor`、旧色值）确认 0 命中，再更新测试用例 |
| 无浏览器自动化 | 课程不要求 Playwright，本地也没有稳定测试环境 | 用静态检查先排除低级错误；v0.2 补 `scripts/screenshot.mjs`，用本机 Edge 无头 + DevTools 协议截图，覆盖桌面/手机/深色/菜单/404 |
| Windows 换行与编码 | 中文文档和脚本在不同工具间容易出现 CRLF 与编码不一致 | 编辑器统一 UTF-8（无 BOM），提交前看 `git diff` 是否整文件变动 |
| 占位简历 | 不能放真实简历，但下载按钮需要能测 | 生成一个最小合法 PDF 占位（约 900 B），链接与下载行为可验证，内容待替换（DEF-02） |
| 移动菜单键盘行为 | `visibility: hidden` 时不可聚焦，但未做焦点陷阱 | v0.2 已补：`Tab` 在菜单内循环、`Esc` 关闭、关闭后焦点回归菜单按钮（DEF-05 关闭） |
| 服务器未购买 | M3 的线上验证无法执行 | 部署配置与脚本先写好并做静态审阅，线上项全部标 ⏳，不写成已通过（DEF-06） |

## 5. 技术收获

- **Git**：分支与提交流程、Conventional Commits、原子提交、用 `git log` 复盘；改版与内容重构分开提交，回滚时可以只退视觉不动内容。
- **Linux 与 Nginx**：通过配置与脚本理解 `apt` 安装流程、`sites-available` / `sites-enabled` 软链、`nginx -t` 校验、`systemctl reload`、`www-data` 属主与 755 权限；实际服务器操作待购买后验证。
- **HTTP 细节**：`try_files` 与自定义 404、`gzip` 压缩类型与最小长度、`expires` 与 `Cache-Control`、`curl -I` 看状态码和响应头。
- **响应式与可访问性**：`clamp()` 流式字号、Grid 与断点、`scroll-margin-top` 解决锚点遮挡、skip-link、`aria-current` / `aria-expanded`、`focus-visible`、`prefers-reduced-motion`、移动菜单焦点陷阱。
- **原生 JS**：`IntersectionObserver` 做进场与导航高亮、`requestAnimationFrame` + `easeOutCubic` 做数字滚动、`localStorage` 持久化、head 内联脚本避免主题闪烁。
- **无头浏览器自检**：用 Edge `--headless=new` + DevTools 协议（`Page.navigate`、`Emulation.setDeviceMetricsOverride`、`Page.captureScreenshot`）截图，不装 Playwright 也能做视觉回归。
- **设计系统落地**：用 CSS 变量管理双主题色板与排版；等宽大写标签、交替区块底色、黄色高亮形成统一「编辑风」；对比度按 WCAG 公式逐组核算，而不是「看着还行」。
- **降级思维**：`.js [data-reveal]` 只在脚本可用时隐藏内容，禁用 JS 也能读完全部信息。

## 6. 不足与改进方向

| 不足 | 影响 | 改进方向 |
|---|---|---|
| 无 HTTPS | 浏览器提示不安全，显得不专业 | 域名 + Let's Encrypt（certbot）自动续期，Nginx 加 301 跳转 |
| 无内容管理后台 | 改一句话要改 HTML 再部署 | 内容抽离为 `content.json`，或引入极简静态生成；短期靠 checklist |
| 内容替换成本高 | 占位多，容易漏改 | 用 `docs/content-checklist.md` 逐项勾选，提交前全局搜索 TODO |
| 无自动化测试与 CI | 回归靠手工走查 + 截图目视 | 加 HTML/CSS lint 与链接检查；GitHub Actions 只做检查，部署仍走云服务器（不使用 Pages） |
| 图片未优化 | 换成真实照片后可能拖慢首屏 | 压缩为 WebP，指定 `width`/`height`，首屏外 `loading="lazy"` |
| 动效克制 | 没有视差、3D、视频背景等「重效果」，视觉冲击力有限 | 保持轻量；若要加，先做性能预算与 `prefers-reduced-motion` 降级 |
| 无访问统计 | 不知道有没有人看 | 属可砍范围，暂不引入第三方脚本 |

## 7. 对「AI 辅助开发」的反思

### 7.1 AI 帮上大忙的环节

- 生成结构与样式的**第一版草稿**，把「空白页恐惧」变成「改草稿」。
- 重复性内容（6 张作品卡、4 组技能标签）的批量生成。
- 文档初稿、Nginx 配置模板、部署脚本与截图脚本骨架，省下查手册的时间。
- v0.2 改版时快速给出白底配色、标签样式与排版候选，缩短「试风格」的周期。

### 7.2 必须人来判断的环节

- **内容真实性**：姓名、学校、项目、邮箱必须自己核对，AI 编不出来也不该编。
- **范围与取舍**：砍什么、留什么，只有自己知道两周内做不做得完。
- **视觉品味**：「像不像参考站」没有量化标准，必须人对着截图判断；AI 只能给候选。
- **安全与权限**：SSH 密钥、服务器权限、`.gitignore` 该忽略什么，必须自己确认。
- **无障碍与文案语气**：对比度是否够、话是否说得像自己，需要人来把关。

### 7.3 用 Git 记录 AI 生成内容

- 一个需求点对应一次提交，提交信息写「做了什么、为什么」，而不是「AI 生成」。
- v0.2 的视觉改版单独提交（`style: 改版为白底编辑风格并移除自定义光标`），与内容重构、文档更新分开，回滚时互不牵连。
- 不把 AI 生成的大段代码和手写修复混在同一个提交里，方便回退与复盘。
- 关键决策（为什么不用框架、为什么先上线、为什么换白底）写进文档，避免日后自己都忘了。

### 7.4 避免直接复制不理解的东西

1. 先通读一遍，能用自己的话讲清这段代码在做什么。
2. 删掉用不上的部分，不保留「以防万一」的死代码。
3. 跑静态检查，再用浏览器实际点一遍。
4. 不确定的写法宁可换简单方案，也不留隐患。

> v0.2 的一条教训：删除一个功能往往比新增更难。自定义光标分散在 HTML、CSS、JS 三处，还出现在测试用例和总结里；AI 容易只改一处，必须全局搜索并跑一次「残留扫描」才算删干净。

## 8. 答辩 / 求职演示建议

### 8.1 30 秒开场

> 「这是一个纯静态的个人作品集，方向是 UE5 × 虚拟制片与影像。站点没有框架、没有构建步骤，两周内按 M0–M5 完成：白底编辑风格、深浅两套主题、移动端菜单带键盘焦点陷阱，配色对比度全部达到 WCAG AA。过程中留下需求、设计、计划、部署手册、测试报告和 AI 使用说明；上线时一条脚本加一份 Nginx 配置就能复现部署。」

### 8.2 三个可展示亮点

1. **视觉与内容一致**：白底编辑风格 + UE5 项目叙事（《回声》《时间切片》《早市》），不是通用模板。
2. **工程细节**：双主题无闪烁、对比度全部 AA、菜单焦点陷阱、无 JS 仍可读、尊重系统「减少动态效果」。
3. **可复现**：`deploy/nginx.conf` + `scripts/deploy.sh` 管部署，`scripts/screenshot.mjs` 管本地视觉自检，gzip、缓存、404、安全响应头都有配置依据。

### 8.3 可能被问到的问题

| 问题 | 回答要点 |
|---|---|
| 为什么不用 Vue / React？ | 单页展示站无数据源，零构建让部署和排错更简单；把复杂度花在内容和可访问性上更值 |
| 为什么改成白底？ | 本人明确要 pudding.cool 那种编辑风；白底 + 彩色标签信息密度高，也更贴合作品集；深色主题保留给夜间浏览 |
| 为什么删掉自定义光标？ | 装饰性功能干扰阅读、对可访问性没有收益；系统光标更稳，也少一个 JS 模块要维护 |

### 9.3 服务器与 Nginx（首次配置）

```bash

sudo nginx -t && sudo systemctl reload nginx
curl -I http://<公网IP>/
```
