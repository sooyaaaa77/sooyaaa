## 3. 关键策略

1. **先上线，再打磨**（Walking Skeleton）：D5 之前必须有公网地址，之后的改动都在"已上线"状态下迭代，避免最后一天才碰服务器。
2. **占位驱动**：先让版式跑通，真实内容按清单替换；不留"等素材再开发"的阻塞点。
3. **每次提交一个可回滚的点**：一次提交只做一件事，信息写清"做了什么、为什么"。
4. **服务器操作即文档**：每条命令、每个报错和解决办法同步写进 `docs/04-deploy.md`。
5. **范围可砍**：时间不足时按顺序砍——作品集 → 深色模式 → 域名/HTTPS → 访问统计；**项目经历、部署、文档、Git 历史不可砍**。

## 6. 风险与预案

| 情况 | 预案 |
|---|---|
| 服务器购买/学生认证受阻 | D2 就开始买；备选学校服务器；最差用本地录屏 + 截图演示 |
| 真实素材持续缺失 | 保留示例内容并在文档中注明，答辩时说明替换计划 |
| 时间不够 | 按第 3 节顺序砍范围，保证核心四项 |
| 部署失败且排查超时 | 回滚到上一份 tar 备份，保证 IP 可访问；把问题记入部署文档 |
| 动效导致手机卡顿 | 降低动效数量，只保留 transform/opacity，开启 reduced-motion 降级 |
